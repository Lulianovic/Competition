# 辣椒场景固件标定

场景/通信层已经把辣椒测距处理为固件使用的毫米值。嵌入式端直接读取 TOF 帧中的 `77.6`，把它当作 **77.6 mm**；代码中的 `/1000` 只用于把毫米转换成机械臂逆解使用的米，不再做任何场景比例缩放。

## 场景实测值

| 项目 | 场景值 | 固件使用值 |
| --- | ---: | ---: |
| AGV 轮距 | 0.972 m | 0.0972 m |
| AGV 轮径 | 0.800 m | 0.0800 m |
| 机械臂底座中心（车体坐标） | (-0.00378, 0.73353, 0.13615) m | 用作传感器标定基准 |
| TOF 发射点（底座右侧） | (0.47571, 0.78603, 0.13615) m | 右向偏移 0.04795 m |
| 颜色发射点（同一前后平面） | (0.47310, 0.68103, 0.13615) m | 与 TOF 上下排列 |
| 首个红椒测距 | 场景已处理 | **77.6 mm（直接读取）** |

车体坐标采用 `+X 前方、+Y 右侧、+Z 向上`。由于两个检测点已转到右侧，固件的抓取目标由原来的 `X=距离、Y=0` 改为：

```text
x = 0 m                     // 与机械臂底座同一前后平面
y = 0.04795 + distance_mm/1000 + 0.0005 m  // 仅 mm→m 单位转换
z = 0.00525 m                // 仅保留测距射线相对机械臂底座的实际高度
```

前后同速行驶不会改变右侧测距，因此颜色有效但距离超出抓取窗时固件停车等待，不再错误地用前进/后退“对距”。当前场景有效测距窗为 50–100 mm；机械臂径向保护为 100–160 mm，覆盖场景中约 56.7–94.6 mm 的实测范围并留出少量误差。

## 巡线起停

2026-10-17 重构为连续比例控制（原离散档位方案作废，其缺陷见
[设计方案01-绕线旋转.md](设计方案01-绕线旋转.md) 第十一节）。控制律集中在
`USER/farm_line_follow.h` 的 `FarmLineFollow_Step()`，参数集中在
`USER/farm_speed_config.h`：

- 位置误差：对压线的各路按权重 (2i-7)（S1=-7 … S8=+7）求平均，得到连续误差
  `err ∈ [-7, +7]`，`err < 0` 线偏左、`err > 0` 线偏右，左右对称时为 0。
  误差连续单调，不存在"线落两传感器间隙却无动作"的死区，也不会在档位间跳变。
- 转向：`turn = FARM_LINE_TURN_GAIN × err`（限幅 `FARM_LINE_TURN_MAX`），
  `左轮 = forward + turn`、`右轮 = forward - turn`，误差一出现即产生纠偏。
- 降速：`forward = FARM_LINE_BASE_SPEED - (BASE - MIN_FORWARD) × |err| / 7`，
  偏离越大前进速度越低，回到中心立即恢复常速。轮速限幅
  `FARM_LINE_WHEEL_MIN/MAX`，下限高于电机起转阈值约 400，避免内轮堵转。
- 丢线（八路全白 `0xFF`）三段式：先按最后采样误差保持修正 200 ms（覆盖线落传感器
  间隙的假丢线）；确属离线后，按"最近的偏离点"`last_dev` 方向以 **2× 正常差速**、
  前进 400 低速旋转回线（内轮可反转、原地转回），时限 3 秒；仍未找回则停车保护。
  偏离点记忆只在误差非 0 时更新，居中直行期不会被 0 覆盖，因此"弯道来不及转
  就跟丢"时仍记得是从哪一侧丢的；从未偏离过则默认向右（顺时针赛道）。
  `|dev| ≤ 5` 为精确 2×（差速 160~800），`|dev| ≥ 6` 饱和于 `LOST_TURN_MAX = 900`。
- 方向契约：S1 视为车体左侧；若实测转向相反，只改 `FARM_LINE_TURN_SIGN` 一处。

验证（主机侧等价整数运算扫描，非仿真/实车）：
- 全部 255 种非全白输入：误差范围均在 ±7 内，转向方向与偏离方向一致，
  轮速均在 `WHEEL_MIN/MAX` 限幅内，无"零误差却左右不同速"的输入。
- 物理上唯一可能的情形（黑线为连续一段，36 种）：`err == 0` ⇔ 加权质心恰好居中，
  无"偏离却不纠偏"的死区；质心越偏 `|err|` 单调不减（-3.5→7、-0.5→1、0→0）。
- 典型值：居中 1000/1000；S5+S6 微偏右 1003/683；S6+S7 中偏右 1006/400；
  仅 S8 大偏右 1010/400，前进速度由 1000 递减至 450。
- 丢线回放（线向右滑出 S5+S6→S6+S7→S7+S8→S8→全白）：阶段① 保持 1× 修正
  20 个周期（差速 560），阶段② 转为 2× 右旋（左 1300 / 右 −500，内轮反转）；
  偏离点记忆 `last_dev=+7` 全程未被清零，旋转方向与丢线侧一致。
固件编译与实车弯道效果仍需在开发环境验证；调参顺序为 BASE_SPEED → TURN_GAIN → MIN_FORWARD_SPEED。

农场场景的起停标志是白色，初始八路全为 `0xff`。2026-09-22 修复了
“刚启动就把白色起点当作停车条件，永远无法驶离”的问题：

- 舵机初始化及原有等待完成后，停车检查红辣椒。连续 500 ms 没有红椒且
  采摘任务空闲才放行；发现红椒时先等待测距、采摘和目标清除，再检查放行。
  正常启动检查开始之前的颜色采样不作为放行依据。
- 放行后允许一次起步直行（左右命令 1000）；黑线巡线速度保持 300。
- 连续检测到黑线 50 ms 后进入正常巡线；之后全白仍停车，不重新启动起步过程。
- 起步行驶累计达到 3 秒仍未找到黑线则停车，复位后才重试。
- 采摘接管底盘期间不会消耗起步行驶时间。
- 日志只记录关键事件：起步检查、发现红椒、夹取、放筐、重试和失败停车。
  不再每秒输出巡线位图、采样计数、运行状态或逆解角度。

仅凭八路全白无法区分白色起点、脱线或未连接的上拉输入，因此保留超时停车。
起步状态机的白色驶离、黑线确认、后续全白、超时及采摘暂停测试通过；
尚未在用户上传固件的仿真环境中验证完整行驶。

## 构建验证

### 偶发采摘结束后停住：通信防阻塞

用户反馈首次运行放入两个辣椒后停住、重启后恢复，无法仅据截图确认根因。
代码检查发现 TCS34725 驱动的总线忙和事件等待原本无超时；此时采摘监测任务
可能无法继续处理动作结束、目标清除及释放底盘。现增加总线忙20ms等待上限，
各事件10000次轮询上限，超时停止事务并重新初始化本机I2C，下一轮自动重试。
只有四通道读取完整成功才发布颜色，失败不计作“未见红椒”，底盘暂停；通信恢复后
继续原状态机。异常/恢复各打印一次，额外增加松爪等待结束及动作指令结束日志。
这些日志表示指令进度，不表示收到场景碰撞或实际夹持反馈。

验证：逐一注入读写各阶段无响应、总线持续忙、RGB半帧失败及下一次读取恢复，
主机测试通过；连续20个目标的尝试预算重置测试通过；固件编译通过。
此改动解决已发现的无限等待路径，未复现用户网页平台的那次偶发停机，仍需上传验证。

### 两次尝试后跳过（最新修订）

每个目标最多尝试两次（首次加一次重试）。动作结束后，连续500ms未见红色则继续；
1秒后仍为红色且收到新的有效测距，则发起第二次尝试。第二次仍失败，或无法取得
新的有效测距，则跳过该目标继续巡线。跳过期间忽略当前红椒，直到连续500ms未见
红色才重新允许采摘并重置次数，避免刚启动又被同一目标叫停。起点处跳过也会放行
原有1000起步流程。放筐规划故障仍保持夹紧停车，与普通夹取失败分开处理。

验证：两次次数上限、1秒等待、无新测距跳过、持续红色不重触发、短暂颜色丢失、
500ms稳定消失后重新计次、计时器回绕测试通过；make -j2 编译通过。
未在用户在线平台验证实际巡线恢复。移除高度补偿的设置保持不变。

### 夹取失败等待与日志精简（历史记录，由上节替代）

旧版 box=3 是等待目标移走，红色仍在时一直停车，没有超时。
新版在动作结束后开始计时：连续500ms未见红色恢复巡线；
3秒后仍为红色且等待期间收到新的50–100mm测距，则重新停车测距再尝试。
总共最多3次（首次+2次重试）。重试耗尽、测距未更新或范围不符则锁定停车，
打印一次明确原因，检查后复位。逆解失败也进入相同重试预算，
放筐规划失败直接保持夹紧停车，不再使用阻塞任务的无限循环。

TOF有效帧由采样任务统一读取；动作前发送读距命令，等待新的有效测距，
不再用缓存值直接启动动作。无效/缺失的TOF不作为“红椒已清除”的证据。
红椒离开颜色视野仅表示可以继续巡线，不能证明已夹住或落筐；
固件仍没有来自场景的实际夹持成功/关节受阻反馈。重试复用现有标定，
没有添加未经验证的碰撞补偿动作。

验证：tests/test_farm_harvest_recovery.c 覆盖3秒等待、2次重试、
重试上限、缺失测距停车、500ms清除确认及计时回绕；测试和交叉编译通过。
尚未在用户在线平台运行本次失败重试流程。

2026-09-22 低速采摘修订：巡线指令从 2000 降为 300，小/中转弯偏移为
60/120，大转弯内外轮为 30/150；按最新要求起步为 1000，限时 3 秒。
采摘只针对红色目标，绿色和蓝色不触发采摘。起步检查及起步状态机测试通过，

任务间隔 20 ms。积分设置仍为 154 ms，20 ms 是轮询周期，不是实际颜色更新周期。
保留原等待式颜色接口供其他调用者使用；清除确认使用实际经过时间，
维持至少500 ms确认时间。新版已通过起步状态机测试和固件编译，
是否能在实际通信环境中及时检测辣椒仍需运行确认。
